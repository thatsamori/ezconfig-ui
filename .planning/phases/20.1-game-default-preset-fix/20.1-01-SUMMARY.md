# Phase 20.1-01 Summary: Game Default Preset Fix

## What Was Built

Fixed the `loadPreset` function in `src/lib/store/configStore.ts` to properly reset all values when loading an empty preset like "Game Default".

### The Bug

When loading the Game Default preset (which has empty `character: {}` and `weapons: {}`):
- The old code only iterated over `state.savedValues` to create tombstones
- This missed any unsaved changes that existed only in `state.workingValues`
- Result: unsaved working values persisted even after loading Game Default preset

### The Fix

Modified `loadPreset` to collect all unique keys from BOTH `savedValues` AND `workingValues` before creating tombstones:

**Character section (lines 492-528):**
```typescript
// Collect all categories from BOTH saved and working values
const allCharacterCategories = new Set([
  ...Object.keys(state.savedValues.character),
  ...Object.keys(state.workingValues.character),
]);

// For each category, tombstone keys not in preset
for (const category of allCharacterCategories) {
  const savedEntries = state.savedValues.character[category] || {};
  const workingEntries = state.workingValues.character[category] || {};
  const presetCategory = presetData.character[category] || {};

  // Collect all keys from both saved and working
  const allKeys = new Set([
    ...Object.keys(savedEntries),
    ...Object.keys(workingEntries),
  ]);

  for (const key of allKeys) {
    if (!(key in presetCategory)) {
      // Key exists in saved or working but not in preset - tombstone it
      if (!newWorkingValues.character[category]) {
        newWorkingValues.character[category] = {};
      }
      newWorkingValues.character[category][key] = null;
    }
  }
}
```

**Weapons section (lines 530-585):**
Applied the same pattern - collecting all weapons and categories from both savedValues and workingValues using Set unions.

## Notes

The save flow (`handleSave` in ActionButtons.tsx) was analyzed and appears correct:
1. Iterates over `workingValues`
2. `buildMergedEntries` merges saved entries with tombstones (tombstones delete keys)
3. Sends result to API (empty `{}` for reset categories)
4. API's `writeCategory` deletes file when data is empty (on-demand storage)
5. `commitWorkingToSaved` updates local state

### Known Limitation: Lazy Loading

Due to lazy loading, only categories that have been visited/loaded can be tombstoned. If a user:
1. Has database files (e.g., `Databases/Character/Combat.json`)
2. Has NOT visited that category in the UI
3. Loads Game Default preset

The database files for unvisited categories will NOT be deleted because `savedValues` doesn't contain them.

**Workarounds:**
- Visit all categories before loading Game Default preset
- Future: Add a "reset all" API that deletes all database files directly

  <name>Task 1: Create preset service layer</name>
  <files>src/lib/presets/service.ts, src/lib/presets/types.ts, src/lib/presets/index.ts, src/lib/env.ts</files>
  <action>
Create a preset service layer following the database service pattern:

1. Add PRESETS_PATH to env.ts (default: "./Presets")

2. Create src/lib/presets/types.ts with:
   - PresetManifest type: { title: string, description: string }
   - PresetInfo type: { name: string, manifest: PresetManifest } (for listing)
   - PresetData type: same structure as saved values in configStore (character + weapons)

3. Create src/lib/presets/service.ts with:
   - getPresetsRoot(): string - returns env.presetsPath
   - getStaticPresetsPath(): string - returns join(getPresetsRoot(), 'Static')
   - validatePresetName(name: string): void - reject path traversal like database service
   - readPresetManifest(presetName: string): Promise<PresetManifest> - reads Static/{name}/manifest.json
   - listStaticPresets(): Promise<PresetInfo[]> - scan Static/ dir, return name + manifest for each
   - loadPresetData(presetName: string): Promise<PresetData> - recursively read preset's JSON files into the savedValues structure format

loadPresetData should:
- Read all JSON files under Presets/Static/{name}/
- Return data in the same shape as configStore.savedValues:
  { character: { [category]: { [key]: value } }, weapons: { [weapon]: { [category]: { [key]: value } } } }
- Follow the existing pattern: Character/ folder → character object, Weapon/{name}/ → weapons[name] object
- Parse JSON files as ConfigEntry[] arrays, extract key-value pairs

4. Create src/lib/presets/index.ts barrel export

Do NOT create a writePreset function - static presets are read-only.
  </action>
  <verify>Create a simple test in the service file (import.meta.main block) that lists presets from a test directory</verify>
  <done>
    - env.ts has presetsPath config
    - Preset types defined
    - Service can list presets and load preset data

  </done>

Create two API endpoints following the databases API pattern:

1. GET /api/presets (src/app/api/presets/route.ts):
   - Call listStaticPresets()
   - Return { success: true, data: PresetInfo[] }
   - Handle errors with { success: false, error: string }

2. GET /api/presets/[name] (src/app/api/presets/[name]/route.ts):
   - Extract name from params
   - Call loadPresetData(name)
   - Return { success: true, data: PresetData }
   - Handle errors (404 for not found, 400 for invalid name, 500 for other errors)
   - Include manifest in response: { success: true, data: PresetData, manifest: PresetManifest }

Follow the existing API patterns:
- Use NextResponse.json
- Log errors to console
- Return appropriate status codes

Create validation utilities that check config entries against the schema:

   - For weapon databases:

   - Return flat map of configKey → schema entry, or null if unknown

2. **`validateConfigEntry(entry: ConfigEntry, schema: Record<string, ConfigEntry>): { valid: boolean; error?: string }`**
   - Entry must have exactly one key
   - Key must exist in schema
   - Value type must match `dataType` from schema:
     - Boolean: `typeof value === 'boolean'`
     - Float: `typeof value === 'number'`
     - FloatArray: `Array.isArray(value) && value.every(v => typeof v === 'number')`
     - Vector2D: `typeof value === 'object' && 'x' in value && 'y' in value && !('z' in value)`
     - Vector: `typeof value === 'object' && 'x' in value && 'y' in value && 'z' in value`

3. **`validateEntries(entries: ConfigEntry[], database: string, category: string): { valid: boolean; errors: Array<{ key: string; reason: string }> }`**

   - Validate each entry

<task type="auto">
  <name>Task 3: Create config API route</name>
  <files>src/app/api/config/[...path]/route.ts</files>
  <action>
Create a catch-all API route that handles both GET and POST for config operations.

**Route structure:** `/api/config/{database}/{category}` where:
- `database` can be simple (`Character`) or nested (`Greatsword` under `Weapon/`)
- `category` is always the last segment (e.g., `Movement`, `Strike`)

**GET handler:**
1. Parse path segments: last segment = category, rest = database path
2. Call `readCategory(database, category)`
3. Return `{ success: true, data: entries }`
4. On error: Return `{ success: false, error: message }` with status 500

**POST handler:**
1. Parse path segments same as GET
2. Parse request body: `{ entries: ConfigEntry[] }`
3. Call `validateEntries(entries, database, category)`
4. If validation fails: Return 400 with `{ success: false, error: "Validation failed", details: errors }`
5. Call `writeCategory(database, category, entries)`
6. Return `{ success: true }`
7. On error: Return 500 with error message

**Path parsing logic for nested databases:**
- `/api/config/Character/Movement` → database="Character", category="Movement"
- `/api/config/Greatsword/Strike` → database="Greatsword", category="Strike"
- The `Weapon/` prefix is handled by `resolveCategoryPath` which checks filesystem structure

Use Next.js App Router conventions (`NextRequest`, `NextResponse`).
  </action>

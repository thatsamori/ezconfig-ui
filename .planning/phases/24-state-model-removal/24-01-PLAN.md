**Current state model:**
- savedValues: Data from API (persisted in database)
- workingValues: User's uncommitted edits (persisted in localStorage)
- hasUnsavedChanges: Computed by comparing working vs saved
- setWorkingValue(): Updates working state only
- setSavedValue(): Updates saved state (used when loading from API)
- commitWorkingToSaved(): Merges working → saved (used by Save button)

**Target state model:**
- values: Single state matching database (no working/saved split)
- setValue(): Async - writes to API, then updates local state
- No localStorage persistence
- hasUnsavedChanges: Always false (remove or deprecate)
</context>

Make `setValue()` and `removeValue()` write directly to API:

1. Create helper function to build merged entries for a category:
```typescript
async function saveToApi(database: string, category: string, entries: Record<string, ConfigValue>): Promise<boolean> {
  try {
    const res = await fetch(`/api/config/${database}/${category}`, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ entries }),
    });
    return res.ok;
  } catch {
    return false;
  }
}
```

2. Update `setValue()` to:
   - Update local state immediately (optimistic update)
   - Call API to persist
   - If API fails, show error toast (import from sonner)
   - Keep local state updated regardless (matches "edit freely" philosophy - if API fails, user can retry)

3. Create `removeValue()` that:
   - Removes key from local state
   - Builds merged entries for the category (excluding removed key)
   - Calls API to persist the updated category

4. Keep synchronous local state updates for responsive UI - API writes happen in background.

5. Since store actions are synchronous by Zustand design, use fire-and-forget pattern:
```typescript
setValue: (database, category, key, value) => {
  set((state) => {
    // Update local state
    const newValues = updateValues(state.values, database, category, key, value);

    // Fire API write (don't await)
    const entries = newValues[isCharacter ? 'character' : 'weapons'][...][category];
    saveToApi(database, category, entries).catch(() => {
      toast.error(`Failed to save ${database}/${category}`);
    });

    return { values: newValues };
  });
}
```

Note: This creates a potential race condition if user edits multiple values quickly. For v2.0 simplicity, we accept this tradeoff - the last write wins. If needed later, we can add debouncing.

1. Create src/app/api/users/route.ts:
   - GET: List all users (returns array without passwords)
   - POST: Create new user { username, password, role }
   - Both require global_admin role (check token, validate role)
   - Return 401 if not authenticated, 403 if not global_admin

2. Create src/app/api/users/[username]/route.ts:
   - GET: Get single user by username (without password)
   - PUT: Update user { password?, role? } - can update password and/or role
   - DELETE: Delete user by username
   - All require global_admin role
   - Cannot delete yourself (prevent admin lockout)
   - Return 404 if user not found

Validation:
- Username: non-empty string, no duplicates on create
- Password: non-empty string on create, optional on update
- Role: must be valid UserRole

Use existing getUsers/saveUsers from service.ts.
Follow token validation pattern from /api/auth/me.
</action>

1. Create src/lib/auth/middleware.ts with helper:
   ```typescript
   export async function requireRole(request: Request, allowedRoles: UserRole[]): Promise<{
     authorized: boolean;
     user?: { username: string; role: UserRole };
     error?: { status: number; message: string };
   }>
   ```
   - Extract token from Authorization header
   - Validate token via validateToken
   - Check if user's role is in allowedRoles
   - Return { authorized: true, user } or { authorized: false, error: { status, message } }

2. Update src/lib/auth/index.ts to export from middleware.ts

3. Refactor /api/users routes to use requireRole helper

This centralizes auth checking for reuse in Phase 18.

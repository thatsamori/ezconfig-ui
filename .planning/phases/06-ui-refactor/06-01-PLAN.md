  <name>Task 1: Refactor configStore for working state model</name>
  <files>src/lib/store/configStore.ts</files>
  <action>
Replace the entire store with a new working state model:

**Remove:**
- characterStaged, weaponStaged (staging checkboxes gone)
- selectedWeapons (no more bulk selection)
- initializeFromGameIni (v0.1 paradigm)
- getStagedChanges (v0.1 paradigm)

**Add state:**
```typescript
interface ConfigState {
  // Saved values (from API, source of truth for UI reset)
  savedValues: {
    character: Record<string, Record<string, ConfigValue>>; // category -> key -> value
    weapons: Record<string, Record<string, Record<string, ConfigValue>>>; // weapon -> category -> key -> value
  };

  // Working values (user edits, not yet saved)
  workingValues: {
    character: Record<string, Record<string, ConfigValue>>;
    weapons: Record<string, Record<string, Record<string, ConfigValue>>>;
  };

  // Loading state per database/category
  loadedCategories: Set<string>; // "Character/Movement", "Greatsword/General"

  // Dirty tracking
  hasUnsavedChanges: boolean;
}
```

**Add actions:**
- `setSavedValue(database, category, key, value)` - populate from API response
- `setWorkingValue(database, category, key, value)` - user edit
- `getEffectiveValue(database, category, key)` - returns working ?? saved ?? undefined
- `markCategoryLoaded(path)` - track lazy loading
- `isCategoryLoaded(path)` - check if already fetched
- `resetWorkingValues()` - discard working, keep saved
- `clearSavedCategory(database, category)` - for reloading from API

**localStorage persistence:**
- On any workingValues change, persist to localStorage key "ezconfig-working"
- On store creation, hydrate workingValues from localStorage
- Compute hasUnsavedChanges by comparing workingValues to savedValues (deep equality check)

**Important:** Use Zustand's persist middleware for localStorage. Import from 'zustand/middleware'.

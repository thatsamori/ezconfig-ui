<task type="auto">
  <name>Task 1: Create permissions helper and apply to config editing</name>
  <files>src/lib/auth/permissions.ts, src/lib/auth/index.ts, src/components/ActionButtons.tsx, src/components/weapons/ConfigRow.tsx, src/components/weapons/ConfigTable.tsx, src/components/character/CharacterConfigTable.tsx</files>
  <action>
1. Create src/lib/auth/permissions.ts:
   ```typescript
   import type { UserRole } from './types';

   export function canEditConfig(role: UserRole | undefined): boolean {
     return role === 'config_editor' || role === 'global_admin';
   }

   export function canManagePresets(role: UserRole | undefined): boolean {
     return role === 'preset_creator' || role === 'config_editor' || role === 'global_admin';
   }
   ```

2. Export from src/lib/auth/index.ts

3. Update src/components/ActionButtons.tsx:
   - Import useAuthStore and canEditConfig
   - Get user from auth store
   - Wrap the entire button group in a conditional: only render if canEditConfig(user?.role)
   - If not allowed, return null (no buttons visible)

4. Update ConfigRow.tsx:
   - Add optional `readonly` prop (boolean)
   - When readonly=true: hide Edit button (Pencil), hide Reset button (X), disable context menu
   - Pass readonly from parent components

5. Update ConfigTable.tsx (weapons) and CharacterConfigTable.tsx:
   - Import useAuthStore and canEditConfig
   - Get user from auth store
   - Pass readonly={!canEditConfig(user?.role)} to ConfigRow components
  </action>
  <verify>npm run build succeeds, TypeScript compiles</verify>
  <done>ActionButtons hidden for viewer/preset_creator, ConfigRow readonly for viewer/preset_creator</done>
</task>

  <action>
1. Import useAuthStore and canManagePresets from auth

2. Get user from auth store

3. Restrict UI based on permissions:
   - Import Preset button: only show if canManagePresets(user?.role)
   - Save Current Config as Preset button: only show if canManagePresets(user?.role)
   - Delete button on user presets: only show if canManagePresets(user?.role)
   - Load button: keep visible for all roles (loading a preset is viewing)

4. For preset_creator role:

   - Loading a preset updates working values but they can't save config changes
   - This is fine - they can preview configs via presets

Note: Load button stays visible because loading a preset just updates working state,
and working state is ephemeral. They won't be able to Save Changes anyway (no ActionButtons).

Create notes module following database service patterns:

**1. src/lib/notes/types.ts:**
```typescript
// Note entry for a config option
export type Note = {
  createdBy: string;  // username who created the note
  note: string;       // note content (plain text)
};

// Notes for a category file - keyed by config option name
// Each option can have multiple notes from different users
export type NotesData = Record<string, Note[]>;
```

**2. src/lib/notes/service.ts:**
Mirror the database service.ts pattern:
- `getNotesRoot()` - returns env.notesPath
- `validatePathSecurity()` - copy from database service (same traversal checks)
- `resolveNotesPath()` - similar to resolveCategoryPath but for Notes root
- `readNotes(database, category)` - read notes file, return empty object if not exists
- `writeNotes(database, category, data)` - write notes file, delete if empty (on-demand storage)
- `cleanupEmptyDirectories()` - copy from database service

Key differences from config service:
- Uses `notesPath` instead of `databasesPath`
- No schema validation needed (notes don't have schemas)
- No containsJsonFiles check (notes are simpler - direct path only)
- File structure: Notes/{database}/{category}.json

**3. src/lib/notes/index.ts:**
Export all types and functions from the module.

**4. src/lib/env.ts:**
Add `notesPath: process.env.NOTES_PATH || './Notes'` to the env config.

  <action>
Create notes API route following config route pattern:

**GET /api/notes/{database}/{category}:**
- Parse path segments (last = category, rest = database)
- Call `readNotes(database, category)`
- Return `{ success: true, data: NotesData }`

**POST /api/notes/{database}/{category}:**
- Parse path segments
- Accept body: `{ notes: NotesData }` - full replacement of notes for that category
- Validate body structure (must be object, each value must be array of Note objects)
- Call `writeNotes(database, category, notes)`
- Return `{ success: true }`

Use the full replacement pattern - UI manages state and sends complete NotesData.
No schema validation needed (unlike config API).

Error responses:
- 400 for invalid path or body
- 500 for filesystem errors

Refactor notes storage from per-category files to per-schema files with config key as top-level index.

Purpose: Notes for a config key (e.g., CanCombo) will be shared across all categories where that key appears.
Output: Simplified notes storage in `Notes/{schema}.json` with config key indexing.
</objective>

<task type="auto">
  <name>Task 1: Update notes service for per-schema storage</name>
  <files>src/lib/notes/service.ts</files>
  <action>
Refactor the notes service:

1. Change `resolveNotesPath(database: string, category: string)` to `resolveNotesPath(schema: string)`:
   - Return `{notesRoot}/{schema}.json` (e.g., `Notes/weapon.json`)
   - Remove the category from the path entirely

2. Simplify `validatePathSecurity` to just validate the schema name (no slashes, no .., alphanumeric only)

3. Update `readNotes(database, category)` to `readNotes(schema: string)`:
   - Just read the single schema file

4. Update `writeNotes(database, category, data)` to `writeNotes(schema: string, data: NotesData)`:
   - Write to single schema file

5. Remove the directory cleanup logic (no longer needed - single file per schema)

6. Add helper function `getSchemaFromDatabase(database: string): string`:
   - If database starts with "Weapon" → return "weapon"
   - If database starts with "Character" → return "character"
   - Otherwise return database.toLowerCase() as fallback
  </action>
  <verify>TypeScript compiles without errors</verify>
  <done>Service updated with per-schema storage functions</done>
</task>

<task type="auto">
  <name>Task 2: Update notes API route for schema-based access</name>
  <files>src/app/api/notes/[schema]/route.ts</files>
  <action>
1. Delete the old `src/app/api/notes/[...path]/route.ts` file

2. Create new `src/app/api/notes/[schema]/route.ts`:
   - GET /api/notes/{schema} - Read all notes for a schema
   - POST /api/notes/{schema} - Write all notes for a schema

3. Simplify the route:
   - No path parsing needed - just use `params.schema`
   - Validate schema is "weapon" or "character" (return 400 for invalid)
   - Use the updated `readNotes(schema)` and `writeNotes(schema, data)` functions

4. Keep the same response format:
   - GET: `{ success: true, data: NotesData }`
   - POST: `{ success: true }` on success
  </action>

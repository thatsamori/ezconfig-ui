Refactor `loadPreset()` to write preset data directly to database:

1. The current implementation builds workingValues with tombstones for deleted keys
2. New implementation should:
   - Clear all existing values that aren't in the preset (delete from DB)
   - Write preset values to DB

Strategy:
```typescript
loadPreset: async (presetData: PresetData) => {
  const state = get();

  // For each category in current values that has data
  // POST the merged result (preset values replace existing)

  // Character categories
  const charCategoriesToUpdate = new Set([
    ...Object.keys(state.values.character),
    ...Object.keys(presetData.character),
  ]);

  for (const category of charCategoriesToUpdate) {
    const presetEntries = presetData.character[category] || {};
    // POST preset entries (empty object clears the file)
    await saveToApi('Character', category, presetEntries);
  }

  // Weapon categories
  const weaponsToUpdate = new Set([
    ...Object.keys(state.values.weapons),
    ...Object.keys(presetData.weapons),
  ]);

  for (const weapon of weaponsToUpdate) {
    const existingCategories = Object.keys(state.values.weapons[weapon] || {});
    const presetCategories = Object.keys(presetData.weapons[weapon] || {});
    const allCategories = new Set([...existingCategories, ...presetCategories]);

    for (const category of allCategories) {
      const presetEntries = presetData.weapons[weapon]?.[category] || {};
      await saveToApi(weapon, category, presetEntries);
    }
  }

  // Update local state to match what we wrote
  set({
    values: {
      character: { ...presetData.character },
      weapons: { ...presetData.weapons },
    },
    // Clear loaded categories since we replaced everything
    loadedCategories: new Set<string>(),
  });
}
```

Since loadPreset is called from PresetsTab.tsx's handleConfirmLoad, the loading state is already managed there. Keep loadPreset synchronous in interface but fire-and-forget the API calls for simplicity.

Actually, make loadPreset async and update the call sites to await it. This ensures preset is fully written before showing success toast.

Note: This means loadPreset needs to return a Promise. Update the interface:
```typescript
loadPreset: (presetData: PresetData) => Promise<void>;
```

Refactor `setBulkWeaponValue()` to write to database for each weapon:

Current implementation updates workingValues for all weapons in a single state update.

New implementation:
```typescript
setBulkWeaponValue: (category: string, key: string, value: ConfigValue, weaponNames: string[]) => {
  // Update local state for all weapons
  set((state) => {
    const newWeapons = { ...state.values.weapons };

    for (const weaponName of weaponNames) {
      newWeapons[weaponName] = {
        ...newWeapons[weaponName],
        [category]: {
          ...newWeapons[weaponName]?.[category],
          [key]: value,
        },
      };
    }

    return {
      values: {
        ...state.values,
        weapons: newWeapons,
      },
    };
  });

  // Fire API writes for each weapon (in parallel for performance)
  const state = get();
  const promises = weaponNames.map((weaponName) => {
    const entries = state.values.weapons[weaponName]?.[category] || {};
    return saveToApi(weaponName, category, entries);
  });

  Promise.all(promises).catch(() => {
    toast.error('Failed to save some weapon configs');
  });
}
```

Handle the case where value is null (reset to game default):
- If value is null, remove the key from the category
- If category becomes empty, the API will delete the file (existing behavior)
